# 整合管理前端

## 目标

在保留当前原版无构建管理前端的基础上，将 v0.9 的 19 个历史页面能力整合为
9 个功能域，减少重复入口和重复上下文，同时恢复 `origin/main` 中已经验收、
但当前备份分支缺少的 v0.9 前端能力。

完成后，用户仍可使用全部已验收能力，但侧栏只呈现其有权使用的业务域；
同一业务域内通过子功能切换完成相关工作。

## 背景

- 当前实现位于 `admin-ui/`，使用浏览器直接运行的 Vue 3、Vue Router 和
  Element Plus，不使用 Vite、npm 构建或新的前端工程。
- 当前实现分支以 `origin/main` 的完整 v0.9 提交 `3849df8` 为基线，包含
  已验收的知识目录、检索诊断、分类审核、知识图谱、Schema 生命周期及相关
  API、权限和测试代码。
- 安全备份分支 `codex/backup-before-frontend-removal-20260724` 保留在
  `d636984`，不在该分支直接实施。
- `docs/12-admin-ui.md` 在 `origin/codex/remove-bundled-frontend` 的
  `010c8f2` 提供了已确认的 9 域功能定义和 19 项历史能力映射。
- 后端 API 和授权是最终事实来源，前端可见性不能替代后端鉴权。

## 功能范围

### 1. 登录

- 保留当前登录体验、Cookie 会话、原目标返回和错误状态。
- 登录后同时加载当前用户、知识库权限和组织成员身份。

### 2. 知识使用

- 在同一工作区整合智能问答、单库检索和联邦检索诊断。
- 智能问答与单库检索要求可读权限；检索诊断只对组织管理员开放。
- 各子功能继续使用现有独立业务组件和后端接口，不在前端重新实现检索逻辑。

### 3. 知识资产

- 在同一工作区整合文档、知识目录和导入/文件替换。
- 恢复严格 current Revision 的知识目录、Evidence、来源文件和处理诊断能力。
- 只读和写入能力按实际权限分别显示，不因合并页面而扩大权限。

### 4. 知识治理

- 在同一工作区整合知识图谱、Schema 管理和分类审核。
- 恢复 `origin/main` 已验收的图谱浏览/治理、Schema 生命周期和分类审核。
- 三套状态机保持独立，不合并命令、状态 fence 或冲突处理。

### 5. 用户与权限

- 将用户生命周期和权限矩阵放入同一平台管理工作区。
- 用户详情是授权写入的唯一入口；知识库反向授权只查看并跳转。
- 仅平台超级管理员可见和可访问。

### 6. 库管理

- 保留现有知识库生命周期、Embedding、重建、来源和 FAQ 能力。
- 仅平台超级管理员可见和可访问。

### 7. 运维中心

- 在同一工作区整合概览、运行状态和任务监控。
- 保持现有部分失败、刷新、任务重试和重建进度能力。
- 仅平台超级管理员可见和可访问。

### 8. 审计中心

- 在同一工作区整合操作审计和问答审计。
- 两类审计继续保持各自的数据授权和内容脱敏边界。
- 平台超级管理员身份不能替代组织客户内容读取权限。

### 9. 账户设置

- 从侧栏移除独立 API Key 入口，通过用户菜单进入账户设置。
- 在同一工作区提供个人资料摘要、允许修改的资料、修改密码、API Key
  管理和退出登录。
- API Key 明文仍只在创建成功后显示一次。

## 导航与兼容要求

- 登录不进入业务侧栏；账户设置通过顶部用户菜单进入。
- 侧栏最多显示 7 个业务域：知识使用、知识资产、知识治理、用户与权限、
  库管理、运维中心、审计中心。
- 每个业务域内部使用稳定的子路由和子功能标签；标签只显示当前用户有权使用
  的能力。
- 旧的 19 个历史地址保留兼容重定向，查询参数必须原样携带到对应新子路由。
- 默认首页选择当前用户第一个真正可访问的业务域，不进入无权子功能。
- 内部跳转、详情回链、Dashboard 快捷入口和测试都迁移到新地址。

## 权限与安全要求

- 恢复 `/me/organizations` 身份投影，并在登录、退出和 401 时与用户权限一起
  初始化或清空。
- 普通 `read`、`insert`、知识库 `admin`、组织管理员和平台超级管理员保持
  不同权限域。
- 知识目录和知识图谱要求有效客户内容 `read`，不能仅凭平台超级管理员访问。
- 检索诊断要求精确的 `organization_admin` 成员身份。
- Schema 和分类审核要求精确的知识库 `admin` 或对应组织管理员身份。
- 危险命令、服务端状态 fence、幂等和 409 重新加载语义保持不变。
- 不新增对象存储地址、凭据、请求头、Prompt、原始异常或任意 Payload 展示。

## 技术约束

- 保留当前 no-build Vue 3 + Element Plus + hash router 架构。
- 不引入 Vite、npm 构建链、TypeScript 迁移或新的前端框架。
- 不覆盖当前原版登录页和整体视觉基线；只补充整合工作区和缺失模块所需样式。
- 优先复用现有页面组件、纯函数和 API 包装器；不复制后端业务规则。
- 实现分支基于 `origin/main` 创建，安全备份分支本身保持不变。
- 不修改无关的未跟踪文件和旧任务目录。

## 不在范围

- 后端 API、数据库模型、权限模型或状态机重写。
- 新增 v0.9 功能文档之外的业务能力。
- 删除历史路由兼容、重新设计品牌、替换组件库或建立新前端工程。
- 把不同审计边界、治理状态机或检索实现强行合并为一套逻辑。
