# 第一性分析

## 公理

1. 回答中的图谱事实必须可回到当前有效原文，否则无法验证真实性。
2. 当前图谱覆盖率有限，因此不能替代现有 RAG。
3. 图检索需要可靠实体种子，自然语言问题本身不是稳定的图遍历入口。
4. 新能力失败时不能降低现有问答可用性。

## 问题本质

核心问题不是“让聊天调用图接口”，而是让跨文档关系在有可靠实体种子和原文证据时提高回答质量，同时保持普通问答不变。

## 被挑战的假设

| 假设 | 判断 | 依据 |
|---|---|---|
| 每个问题都查询图谱 | 舍弃 | 图谱覆盖有限，并会给普通问题增加延迟 |
| 图谱应先于向量检索 | 改为 RAG 先行 | RAG 命中切片可提供受治理的实体种子 |
| 每次用 LLM 识别实体 | MVP 舍弃 | 会增加成本、延迟和无约束名称猜测 |
| 默认使用两跳 | MVP 舍弃 | 一跳已覆盖直接关系且更容易控制噪声 |
| 实体关系文本可直接进入 Prompt | 改为必须回查 Evidence | 图标签不是事实证据 |
| 图谱失败应使问答失败 | 舍弃 | 图谱是增强层，RAG 仍可独立工作 |

## Ground Truths

1. 当前聊天只调用 `run_retrieval`，未将图检索结果加入回答 Prompt。
2. 当前图检索可按实体 ID 查询 active Publication，并返回 Evidence locator。
3. Chunk、EntityMention、RelationEvidence 和 Publication item 已有可关联身份。
4. 当前 v0.6 遍历支持一至两跳、Publication fence 和有界结果。
5. 当前测试库关系覆盖稀疏，不足以让图谱成为主检索。

## 推导

- GT1 + GT3：先复用 RAG 命中切片生成实体种子，避免新增模型调用。
- GT2 + 公理 1：只允许 active Publication 中具备当前有效 Evidence 的关系进入上下文。
- GT4 + GT5：MVP 限制为一次、一跳、有界查询，并在失败时退回 RAG。
- 结论：增加一个薄的图谱上下文编排层，而不是重写现有检索或回答流程。

## 验证

- 所有结论均可追溯到 Ground Truth 或公理。
- 主要失败模式包括实体种子错误、图谱稀疏、Evidence 失效和额外延迟，分别通过 RAG 先行、Publication/Evidence fence、有界查询、影子模式和自动降级控制。
