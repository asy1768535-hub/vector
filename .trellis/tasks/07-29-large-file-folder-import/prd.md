# 大文件与文件夹导入

## 目标

让用户能够稳定上传现实业务中的大型文档，并能一次选择包含多层嵌套目录的文件夹，自动收集其中可导入的文件，不再需要逐层手工选择。

## 已确认事实

- 当前前端和后端都将单文件上限固定为 50 MiB。
- 当前 `/libraries/{slug}/import-file` 在 HTTP 请求内把完整文件读入内存，随后同步解析和切片。
- Embedding、知识图谱抽取已有后台任务，但文件解析与切片仍是同步步骤。
- 当前对象存储适配器以完整 `bytes` 为输入，不能直接承接大文件流。
- 当前上传页逐文件调用导入接口，每批最多 20 个文件。
- 浏览器目录选择可通过 `webkitdirectory` 返回所有后代文件，并在 `File.webkitRelativePath` 中提供相对路径。
- 仓库已有 `folders` 表、目录 CRUD API、`ensure_folder_path()` 和 `documents.folder_id`，但当前文档页面没有目录树，也未在文件上传中使用目录能力。

## 需求

### R1 单文件大小

- 单个文件最大允许 500 MiB。
- 限制由后端配置统一公布，前端不得重复硬编码。
- 超限文件应在上传前标记为不可上传，后端仍必须执行同样的硬限制。

### R2 文件夹选择

- 上传区同时提供“选择文件”和“选择文件夹”入口。
- 选择文件夹时递归收集全部后代文件。
- 导入后长期保留所选根目录及其全部有效子目录层级。
- 知识库文档页面提供目录树浏览；文档归属到原文件所在目录。
- 自动接受 `.txt`、`.md`、`.markdown`、`.json`、`.csv`、`.docx`、`.xlsx`、`.pdf`。
- 不支持、超限、重复的文件不得静默丢弃；界面汇总显示跳过数量和原因。
- 队列显示相对路径，以区分不同子目录中的同名文件。
- 文件夹导入不适用于“替换单个文档”；替换流程仍只接受单文件。
- 单次文件夹选择最多加入 1000 个有效文件。
- 浏览器同时上传最多 2 个文件。

### R3 大文件处理

- 浏览器将文件拆成固定大小的数据块上传；单块失败可重试，并可查询服务端已接收偏移。
- HTTP 层将数据块流式落入暂存存储，不在内存中拼接完整文件。
- 上传接收完成后创建持久化导入任务并立即返回任务标识。
- 后台任务执行格式校验、解析、切片、文档 Revision 创建和 Embedding 排队。
- 任务状态至少覆盖：上传中、等待处理、解析、切片、等待向量化、向量化、知识图谱构建、完成、失败。
- 失败可重试；孤立暂存文件和终态任务按保留策略清理。
- 当前同步导入接口需要保留兼容期，避免现有替换、权限和 API 使用方突然失效。
- 用户刷新页面后可恢复任务状态；由于浏览器安全限制，继续传输尚未完成的本地文件时需要用户重新选择同一文件或目录。

### R4 安全与权限

- 继续使用知识库 `insert` 权限。
- 后端重新校验文件类型、大小、图谱开关、安全级别和 Schema 可用性。
- 相对路径必须规范化，拒绝绝对路径、盘符、`..` 和路径穿越。
- 500 MiB 是每个文件上限，不代表允许无限并发；服务端必须限制同时处理的大文件数。
- 后台文件解析并发固定为 1 个，后续通过配置调整。

## 验收标准

- 选择一个含多层目录的文件夹后，所有支持格式的后代文件进入上传队列。
- 两个不同目录中的同名文件能在队列中通过相对路径区分。
- 导入完成后刷新页面，目录树和文档归属保持不变。
- 500 MiB 以内文件通过前后端大小校验，超过上限的文件在前端和后端都被拒绝。
- 上传大文件时，API 进程的内存占用不随文件大小线性增长。
- 上传完成后刷新页面，仍能查看导入任务状态。
- 解析、切片、Embedding 和知识图谱进度在同一队列行中连续展示。
- 任一任务失败不阻塞同批其他文件，失败项可以单独重试。
- 原有单文件上传、单文件替换、批量替换和图谱抽取开关继续工作。

## 暂不纳入

- 跨设备自动续传。
- ZIP/RAR 自动解压。
- 浏览器不提供目录选择能力时的非标准兼容方案。

## 关键决策

- 再次导入同一目录时，以规范化相对路径作为文件身份：内容未变化则跳过，内容变化则创建新 Revision。
- 本次文件夹中缺失的历史文件不自动删除。
- 单次最多 1000 个文件，浏览器上传并发 2，后台解析并发 1。
