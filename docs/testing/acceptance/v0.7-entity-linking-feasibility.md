## Deterministic Retrieval Control Contract

### 1. Scope / Trigger

Release evidence v8 is an immutable `NO_GO`: all three v9 post-freeze runs passed their
26 per-run gates, but dense and hybrid evidence-set hashes changed across independently
rebuilt Qdrant collections. Candidate and exact-only response hashes were stable. This
corrective implementation may stabilize the old retrieval controls, but it is not release
authority and must not rewrite or reinterpret the v9/v8 chain.

### 2. Signatures

```python
qdrant.search(..., limit: int, exact: bool = False) -> list[dict]
run_retrieval(..., candidate_k: int | None = None,
              exact_vector_search: bool = False) -> DifyRetrievalResponse
```

### 3. Contracts

- Normal production callers retain their existing candidate count and approximate-search default.
- The deterministic control explicitly uses `candidate_k=50` and `exact_vector_search=True`.
- The manifest records the exact-search and tie-completion algorithm version; drift changes the
  frozen control-config hash and invalidates the run.
- Exact search requests one item past the boundary, then expands only when the requested cutoff is tied.
- Probe limits are `51`, `102`, and at most `201` for a requested candidate pool of `50`.
- Returned hits are ordered by score descending, then immutable `chunk_id` ascending.
- RRF inputs are independently ordered by score and `chunk_id`; fused ties use dense rank,
  keyword rank, then `chunk_id`. Reranker score ties use original candidate index.

### 4. Validation & Error Matrix

- `limit < 1` -> `ValueError`.
- `candidate_k < 1` -> `ValueError`.
- `candidate_k > visibility_overfetch_max` -> `ValueError`.
- Exact `limit >= 201` -> `ValueError` because no bounded probe slot remains.
- An exact-search tie still crossing the requested cutoff at probe limit `201` ->
  `QdrantDeterminismError`; no arbitrary result is returned.
- Missing payload `chunk_id` -> Qdrant point ID is the stable fallback key.

### 5. Good / Base / Bad Cases

- Good: 64 equal-score points inserted in opposite orders return the same ordered Top 50.
- Base: no cutoff tie performs one exact query with `limit=51` and returns Top 50.
- Bad: more than 201 equal-score points crossing the cutoff fail closed.

### 6. Tests Required

- Unit: exact request payload, score/ID order, adaptive tie expansion, and overflow failure.
- Unit: RRF results are invariant to dense/keyword input order.
- Unit: reranker equal scores are ordered by candidate index.
- Live Qdrant: rebuild two disposable collections with reversed insertion order and assert
  identical ordered IDs; delete both collections afterward.

### 7. Wrong vs Correct

Wrong: fetch an arbitrary Top 50 and sort only those hits; equal-score membership may
already differ at the Qdrant cutoff. Correct: probe past the cutoff, expand until the tie
is complete within the hard bound, apply stable ordering, and fail closed if the bound
cannot prove a deterministic result.
