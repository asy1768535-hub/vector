# v0.4 Graph Extraction Evaluation Runbook

This runbook covers the isolated v0.4 graph extraction evaluation path. All real-provider runs use committed synthetic
data, dedicated PostgreSQL databases, immutable sanitized artifacts, and the frozen DeepSeek provider contract.

## Frozen Release Contract

```text
provider: deepseek
base URL: https://api.deepseek.com/v1
model: deepseek-v4-pro
release dataset: release-v1
policy: eval_policy_v1
policy SHA-256: 9fd5652e9ed7d0b585feb6dd57d12aad7c3a4ecf7a85a4159d44f947464ccc3b
release manifest semantic SHA-256: 8cb812a33dac20745b78cca342a27e065684032a25e7adc020cc3d0ad19b5d22
release content semantic SHA-256: 6b316cbbcfc7357cb27bb0b8500e8c49ec041ce2d85c52715aba7108c3d6e96b
evaluation config SHA-256: abac93e3e86a5d198708410e6c6046f14a14d0e150970940983eea1b73f2d54a
```

Do not substitute another model, base URL, prompt, parser, ontology, policy, or dataset under `eval_policy_v1`. Any such
change requires a new calibration, a new policy version, and three new post-freeze runs.

## Safety Rules

- Only manifests under `eval/graph_extraction/manifests/` may be sent to the Provider.
- Never use a production document, shared staging database, or existing Eval database.
- Keep Provider credentials in the process environment or local ignored `.env`; never pass them on the command line.
- Require an exact `--confirm-external-send` value matching the synthetic dataset ID.
- Start selected Release runs only from a tracked-clean tree. Existing result files are immutable.
- Keep `GRAPH_EXTRACTION_AUTO_TRIGGER_ENABLED=false` for Eval.
- Retain every Eval database until its artifact has been verified and release acceptance is complete.

## Prerequisites

Use the repository virtual environment and a PostgreSQL role that may create dedicated `vkt_m6_eval_*` databases.
Configure the process without printing values:

```powershell
$env:VECTOR_KB_M6_EVAL_ADMIN_DSN = "postgresql+asyncpg://<user>:<password>@<host>:5432/<admin-db>"
$env:GRAPH_EXTRACTION_API_KEY = "<deepseek-key>"
$env:GRAPH_EXTRACTION_ENABLED = "true"
$env:GRAPH_EXTRACTION_AUTO_TRIGGER_ENABLED = "false"
$env:GRAPH_EXTRACTION_BASE_URL = "https://api.deepseek.com/v1"
$env:GRAPH_EXTRACTION_MODEL = "deepseek-v4-pro"
```

The API key must be budgeted for the planned calls. The Release manifest has 120 Units, so a clean run normally makes
120 calls. Timeouts and retries increase both cost and `real_model_call_count`. Use bounded workers; the accepted v1
runs used `--workers 4` and each took about 16-17 minutes.

## Offline Dataset Validation

This command must not load application Settings, a database, or the network:

```powershell
python scripts/graph_extraction_eval.py validate `
  --manifest eval/graph_extraction/manifests/release_v1.json
```

Expected semantic hashes are the manifest/content hashes listed in the frozen contract above. Canonical parsed JSON is
hashed, so newline conversion does not change the semantic result.

## Real Development Smoke

Use a fresh run ID and database name:

```powershell
python scripts/graph_extraction_eval.py run `
  --phase development-smoke `
  --manifest eval/graph_extraction/manifests/development_smoke_v1.json `
  --database vkt_m6_eval_smoke_<unique-suffix> `
  --run-id development-smoke-v1-<unique-suffix> `
  --workers 4 `
  --real-provider `
  --confirm-external-send development-smoke-v1 `
  --retain-database
```

Smoke validates the Provider envelope, strict parser, Attempt accounting and Evidence binding. It does not freeze a
policy and cannot count as a post-freeze Release run.

## Calibration And Policy Freeze

Calibration uses the complete Release manifest and `--phase calibration`. It requires at least 100 real calls but does
not count as one of the three post-freeze runs. After a successful calibration, stop automation and obtain explicit
human approval for all four thresholds, approver identity, UTC approval time, and an approval reference. Commit the
policy before any post-freeze run starts; never amend the policy commit.

## Post-Freeze Release Run

Run three times sequentially. Each invocation needs a new database and run ID, and each result must be verified and
committed before the next starts:

```powershell
python scripts/graph_extraction_eval.py run `
  --phase post-freeze `
  --manifest eval/graph_extraction/manifests/release_v1.json `
  --policy eval/graph_extraction/eval_policy_v1.json `
  --database vkt_m6_eval_postfreeze_<unique-suffix> `
  --run-id post-freeze-release-v1-<unique-suffix> `
  --workers 4 `
  --real-provider `
  --confirm-external-send release-v1 `
  --retain-database
```

Every run independently requires succeeded Jobs/Units, at least 100 real calls, JSON parse rate at least `0.99`, schema
valid rate at least `0.95`, all four frozen precision/recall thresholds, zero cross-revision Evidence, and zero Eval
formal writes. Do not average runs.

## Failure And Interruption

- Preserve a sanitized failed artifact when the database can still be read.
- Never edit, overwrite, or delete an artifact to make a result pass.
- Never resume under a consumed run ID or database name. Audit the retained database, then use a new pair.
- Original-Job retry may preserve failed Attempts before a later success; those Attempts remain in all denominators.
- A production behavior, prompt, model, dataset, ontology, or policy change invalidates the selected run sequence.
- A rate-limit or billing failure is operational evidence, not a passing result.

## Offline Release Verification

Clear real-run secrets and verify the evidence bundle without database or network access:

```powershell
Remove-Item Env:GRAPH_EXTRACTION_API_KEY -ErrorAction SilentlyContinue
Remove-Item Env:VECTOR_KB_M6_EVAL_ADMIN_DSN -ErrorAction SilentlyContinue
python scripts/graph_extraction_eval.py verify-release `
  --evidence eval/graph_extraction/release_evidence_v1.json
```

The verifier checks referenced file SHA-256 values, the selected calibration, the exact policy, three distinct
post-freeze identities, common dataset/config hashes, Provider/model identity, call floors, all metric gates, and formal
safety counts.

## Retained Database Audit

Before disposal, connect with a read-only PostgreSQL role or `default_transaction_read_only=on` and recompute the
artifact projection for every real result. At minimum verify:

```text
alembic_version = 0022
Job IDs exactly match the artifact
Job, Unit and Attempt status counts exactly match
Provider request-ID count and digest exactly match
metric numerators and denominators exactly match
cross-revision Evidence = 0
Eval-created formal rows = 0
```

The v0.4 acceptance run recomputed all six retained real artifacts, including the historical failed DashScope smoke,
and obtained exact equality.

## Purge And Disposal

Do not purge before acceptance because Context, Attempt and Candidate rows are audit evidence. After sign-off:

- application databases use `purge_document_graph_extraction_payloads`,
  `purge_revision_graph_extraction_payloads`, or `purge_expired_graph_extraction_payloads` from
  `app.services.graph_extraction_purge` inside an operator-controlled transaction;
- dedicated Eval databases may be dropped after their artifact has been recomputed and retained evidence is backed up;
- clear `GRAPH_EXTRACTION_API_KEY`, `VECTOR_KB_M6_EVAL_ADMIN_DSN`, and any temporary acceptance variables from the
  process environment.

Never point purge or database-disposal operations at a shared database without a reviewed backup and explicit scope.
