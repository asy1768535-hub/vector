# v0.3 Graph Relation Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the first graph/relation foundation layer by binding entities, mentions, relations, and relation evidence directly to v0.2 `evidence_units.id`.

**Architecture:** Keep the current PostgreSQL, SQLAlchemy, FastAPI, and evidence-first architecture. Add relational graph foundation tables and APIs on top of the v0.2 revision/evidence model; do not introduce an external graph database, graph retrieval path, GraphRAG, QA flow, extraction worker, or UI in this phase. `entity_mentions.evidence_id` and `relation_evidence.evidence_id` are the standard evidence anchors and must not depend on `chunk_id`.

**Tech Stack:** Python 3, pytest, FastAPI, Pydantic v2, SQLAlchemy async ORM, Alembic, existing `require_lib()` permissions, existing v0.2 evidence read semantics.

## Global Constraints

- Base branch is `v03-graph-relation-foundation` at `b047e58`.
- Keep current v0.2 Evidence Foundation behavior unchanged.
- Do not mix the stashed chat score diff into this work.
- Do not modify release history or v0.2 migration semantics.
- Do not implement ontology/schema registry tables, automatic LLM extraction, graph extraction jobs, GraphRAG, graph QA, graph visualization, governance UI, Neo4j, OpenSPG, or KAG integration.
- Additive v0.3 tables must bind graph records to `evidence_units.id`; no v0.3 graph table may require `chunk_id`.
- Follow the v0.2 nullable-first migration style and keep old APIs compatible.
- New graph API endpoints must be feature-flagged off by default.
- All graph writes must enforce library scope and active evidence scope.
- Follow TDD: write a failing test, run it red, implement the minimal code, run it green before moving to the next behavior.

async def require_graph_evidence(db: AsyncSession, library: Library, evidence_id: uuid.UUID) -> EvidenceUnit:
    evidence = await db.get(EvidenceUnit, evidence_id)
