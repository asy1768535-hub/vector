# v0.2 Evidence Foundation M2 Write Path Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Switch document writes, behind `ENABLE_EVIDENCE_WRITE_PATH`, so new or changed writes create `document_revisions`, `document_blocks`, `evidence_units`, revision-aware `chunks`, `chunk_blocks`, `chunk_evidence`, and revision-aware `embedding_jobs`.

**Architecture:** Keep the legacy write path as the default. Add a focused evidence write helper that turns existing text/chunk inputs into one pending `DocumentRevision`, one block/evidence pair per chunk, linked chunk rows, and an embedding job with both legacy integer revision and new revision UUID fields. API status-code and response-shape changes are additive and gated by the same flag.

**Tech Stack:** Python 3.10+, FastAPI, Pydantic settings, SQLAlchemy 2.0 async ORM, pytest.

## Global Constraints

- M2 scope only: write path switching and metadata guardrails for write APIs.
- Do not modify worker job claiming, embedding, Qdrant payload construction, Qdrant point IDs, publication, retrieval visibility, cleanup outbox semantics, folders APIs, sync source APIs, evidence read APIs, or graph code.
- Keep compatibility fields: `documents.current_revision`, `embedding_jobs.document_revision`, existing chunks, and old response `status` remain available.
- Feature flag default is `False`; old tests and runtime behavior remain unchanged unless `ENABLE_EVIDENCE_WRITE_PATH` is enabled.
- With the flag enabled, changed writes return `202 Accepted`; no-op writes return `200 OK`.
- New revisions are created as `pending` and set `documents.latest_revision_id`; M2 does not publish `documents.current_revision_id`.
- Direct service calls still return the current tuple signatures used by callers.
- Metadata validation rejects reserved fields and reserved namespaces with an exception that API maps to HTTP `422`.
- Use TDD: write failing tests first, confirm expected failure, implement minimal code, then verify green.
- Existing dirty chat files must not be edited, staged, or reverted.

## File Structure

Create:

- `app/services/metadata_guard.py`: validates external metadata is a bounded JSON object and does not use reserved system keys/namespaces.
- `app/services/evidence_write_path.py`: builds M2 revision/block/evidence/chunk/job rows from the current ingest inputs.
- `tests/test_v02_m2_write_path.py`: feature-flagged service and API tests for M2.

Modify:

- `app/config.py`: add `enable_evidence_write_path: bool = False`.
- `app/services/ingest.py`: when the flag is enabled, validate metadata and call the evidence write helper for new writes and changed reingest.
- `app/api/documents.py`: when the flag is enabled, return `202` for changed writes, `200` for no-op, and map metadata guard errors to `422`.
- `app/schemas/documents.py`: add additive response fields `document_status`, `revision_status`, `job_status`, and `document_revision_id`.

Do not modify:

- `app/workers/embedder.py`
- `app/services/retrieval.py`
- `app/services/visibility.py`
- `app/services/cleanup.py`
- Qdrant services
- Alembic migrations
- graph or ontology modules

## Self-Review

- M2 plan contains no graph, ontology, entity, relation, worker, retrieval, Qdrant, folder API, sync API, or evidence read API implementation.
- `current_revision_id` is not published by M2.
- `latest_revision_id` points at the newest pending revision.
- Response fields are additive and legacy `status` remains.
- Changed write `202`, no-op `200`, metadata guard `422` are covered by tests.
- Rollback is feature-flag based: disabling `ENABLE_EVIDENCE_WRITE_PATH` returns to the legacy path.
