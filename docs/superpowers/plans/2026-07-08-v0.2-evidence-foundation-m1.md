# v0.2 Evidence Foundation M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement only M1: schema, SQLAlchemy models, Alembic migration, legacy backfill scripts, and migration tests for v0.2 Evidence Foundation.

**Architecture:** M1 is a nullable-first database foundation. It adds the evidence model tables and revision/chunk provenance columns, then provides an offline, resumable, idempotent backfill path for legacy active documents and chunks. It does not switch write path, worker publication, retrieval visibility, Qdrant payloads, folders/sync APIs, or evidence/source APIs.

**Tech Stack:** Python 3.10+, FastAPI codebase conventions, SQLAlchemy 2.0 ORM, Alembic, PostgreSQL UUID/JSONB, pytest, optional real PostgreSQL migration tests gated by `VECTOR_KB_PG_TEST_DSN`.

## Global Constraints

- M1 scope only: schema/models/migration, backfill scripts, migration tests.
- Do not change worker, retrieval, write path, Qdrant payload construction, cleanup behavior, public APIs, metadata validation, parser adapters, or graph-related code.
- Do not implement v0.3 ontology, entities, relations, mentions, relation evidence, graph extraction, graph retrieval, graph QA, or governance UI.
- Keep compatibility fields and behavior: `documents.current_revision`, `embedding_jobs.document_revision`, and existing Qdrant `payload.document_revision` remain authoritative for current runtime paths.
- New columns added to existing tables must be nullable in M1.
- New tables may define their own primary keys and core required columns, but M1 must avoid adding strict foreign-key or NOT NULL constraints to legacy rows through existing-table columns.
- Legacy deleted documents are skipped by default. If later an audit backfill is added, their revision status must be `deleted`; that is outside this M1 implementation plan.
- For M1 backfill, "legacy active document" means `documents.deleted_at IS NULL`. `current_revision_id` is set only when the generated revision represents the document's current visible legacy revision.
- Backfill must be deterministic and idempotent: retrying must generate the same revision, block, evidence, and link IDs for the same legacy document/chunk inputs.
- Backfill must be resumable through `migration_backfill_state`.
- Existing dirty chat files must not be edited, staged, or reverted: `admin-ui/chat_redesign.test.mjs`, `admin-ui/src/views/Chat.js`, `app/api/chat.py`, `app/schemas/chat.py`, `tests/test_chat_api.py`.
- Use TDD for implementation: write failing tests first, confirm expected failure, then implement the minimal code.
- Use `apply_patch` for manual edits.

"""v0.2 evidence foundation m1

Revision ID: 0018
Revises: 0017
Create Date: 2026-07-08
"""
from __future__ import annotations

from typing import Sequence, Union

import sqlalchemy as sa
from alembic import op
from sqlalchemy.dialects import postgresql


revision: str = "0018"
down_revision: Union[str, None] = "0017"
branch_labels: Union[str, Sequence[str], None] = None
depends_on: Union[str, Sequence[str], None] = None

import argparse

    parser.add_argument("--batch-size", type=int, default=100)

        )

            return


if __name__ == "__main__":
