ordinal-1 `link_graph` durations copied `linker` durations. G2.1 corrects measurement and
does not lower `500 ms` or `1500 ms` limits.

### 0A.3 Scorer V2

`lexical-score-v2` uses only `normalize_graph_name_v1` output and integer-half-up
arithmetic. It keeps the v1 base score:

```text
base = max(character_bigram_dice, token_jaccard, substring_containment)
```

For normalized mention `m` and canonical name `c`, boundary omission is eligible only
when `len(m) >= 2`, `len(m) < len(c)`, and `c.startswith(m) or c.endswith(m)`:

```text
support = ratio_micros(len(m), len(c))
boundary_score = 850000 + round_half_up(150000 * support / 1000000)
```

Ordered abbreviation is eligible only under the existing initialism or strict ordered
subsequence predicate, including the non-contiguous and `<= 0.75` ratio guards:

```text
support = max(character_bigram_dice,
              ratio_micros(len(compact(m)), len(compact(c))))
abbreviation_score = 850000 + round_half_up(150000 * support / 1000000)
```

Ineligible structured scores are zero. The final score is
`max(base, boundary_score, abbreviation_score)`. Exact-first behavior, type hard filter,
candidate floor `500000`, maximum candidates `10`, stable ordering, and the original
25-point score/margin grid remain unchanged. Aliases, embeddings, LLMs, dictionaries,
pinyin/transliteration, dependencies, new data sources, and label/category-aware scoring
are forbidden. Reference and production scorers remain independent and must conform
bit-for-bit on the complete v2 corpus.

### 0A.4 Dataset, Cohorts, Holdout, And Decoys

G2.1 creates new `gold_v2.json`, `cases_v2.jsonl`, `conformance_v2.json`, and
`manifests/feasibility_v2.json`; v1 files remain immutable.

```text
calibration: 40 safety + 40 utility = 80
holdout:     40 safety + 80 utility = 120
```

The 80 holdout utility cases contain exactly 20 cases per frozen hop/script stratum.
Utility cases contain only linkable required mentions. Safety cases remain first-class
intrinsic evidence but do not enter retrieval utility aggregates. Candidate, dense, and
hybrid utility plus paired bootstrap use the exact same utility case IDs and never drop
empty outputs.

Calibration and holdout entity, mention, relation-template, phrase, and decoy families
are disjoint. Before policy freeze the evaluator may verify holdout bytes, hashes,
counts, and family isolation, but may not score holdout mentions, execute holdout
retrieval, or emit holdout responses/metrics.

Every utility case has one formal gold chunk and exactly 12 ordinary same-publication
non-gold decoys: four surface/title, four relation-language, and four partial-context
decoys. Questions/gold chunks do not share artificial case suffixes or fixed boilerplate.
No retrieval-visible field marks gold or decoy status. Candidate graph retrieval receives
only linked entity seeds and no gold evidence, relation type, direction, path, or answer.

### 0A.5 Calibration Selection

A grid row is eligible only under all original zero-error/precision/exact/scope/privacy
conditions and when at least `32/40` calibration utility questions link every required
mention and execute graph retrieval. Eligible rows are ordered by:

1. higher utility-question execution count;
2. higher non-exact correct auto-link count;
3. higher minimum score;
4. higher minimum margin.

No eligible row is `NO_GO`. Holdout outcomes cannot participate in selection. After one
new calibration, automation stops for explicit approval of the exact artifact path,
canonical SHA, file SHA, and four threshold fields before policy creation.

### 0A.6 Performance V2

The 6,000-Entity performance contract has two fixed scenarios:

- `linker-mixed-10`: two exact, three high-similarity, three ambiguous, two not-found;
  measures the full linker and does not call graph retrieval.
- `link-graph-linked-10`: ten safely linkable mentions; every measured repetition must
  execute the complete link+graph path.

Each candidate/control path runs the same scenario for five actual warm-ups followed by
30 measured repetitions. Different questions cannot count as repeats, duration vectors
cannot be copied, and graph execution is an explicit artifact/verifier field. Existing
absolute, ratio, SQL, N+1, projection, memory, and timeout gates remain unchanged.

## 5. Canonical JSON 与 Hash 合同

### 5.1 Canonical bytes

G3 evaluation 可只读复用 accepted `app.services.graph_canonical.canonical_graph_json_v1`，不得修改它。所有 JSON
schema 都 `extra='forbid'`、duplicate-key reject、UTF-8、finite-number-only。固定 bytes：

```text
canonical JSON value:
  object keys lexicographic ASC
  array order preserved unless schema explicitly requires sorted input
  ensure_ascii=false
  separators=(',', ':')
  allow_nan=false

.json file bytes:
  canonical JSON UTF-8 bytes + one LF

.jsonl file bytes:
  one canonical object per line, one LF per object, no blank line
```

Loader 拒绝 BOM、CRLF、invalid UTF-8、duplicate key、trailing whitespace、extra field、wrong ordering、noncanonical
bytes、NaN/Infinity 和 symlink/path escape。

### 5.2 Artifact reference

统一 strict type：

```json
{
  "repository_relative_path": "eval/entity_linking/...",
  "canonical_sha256": "64-lowercase-hex",
  "exact_file_sha256": "64-lowercase-hex"
}
```

`canonical_sha256` 对 parsed full body 的 canonical JSON bytes 计算，不含 trailing LF；`exact_file_sha256` 对磁盘
完整 bytes 计算。Artifact body 绝不保存自身 path/hash。Writer 原子写入、read-back 后只在 CLI output 发布自身
三元组；下游 body 保存上游三元组，verifier 重新计算。Release evidence 自身 hashes 只由 final CLI 和 completion
record 外部发布。

### 5.3 Dataset identities

```text
gold_content_sha256
  = SHA-256(canonical parsed gold_v1)

cases_content_sha256
  = SHA-256(canonical ordered array of parsed cases_v1 JSONL records)

conformance_content_sha256
  = SHA-256(canonical parsed conformance_v1)

dataset_content_sha256
  = SHA-256(canonical object containing the three content hashes,
    their schema versions and dataset_id)

dataset_manifest_sha256
  = SHA-256(canonical parsed feasibility_v1 manifest)

evaluation_config_sha256
  = SHA-256(canonical controls, scorer, threshold grid, bootstrap,
    performance and metric-population config from the manifest)
```

Manifest body references gold/cases/conformance path/canonical/file hashes but never its own hash。Validator 的 CLI
output 外部发布 manifest canonical/file hashes。

### 5.4 Code identities

`reference_scorer_sha256` 是 `reference_scorer.py` exact file hash。`evaluation_tree_sha256` 是 Section 4 code/test/
script path 与 exact file hash 的 canonical ordered map。

Accepted production dependency identity 不使用手写开放集合。固定
`dependency_closure_algorithm=app-python-ast-import-closure-v1`，exact root modules 为：

```text
app.config
app.models.library
app.schemas.dify
app.schemas.v06_graph_retrieval
app.services.embedding
app.services.graph_canonical
app.services.graph_normalization
app.services.graph_publication_read
app.services.graph_retrieval
app.services.keyword_search
app.services.qdrant
app.services.retrieval
app.services.source_enrichment
app.services.visibility
```

Closure builder 必须使用 Python AST，不 import/execute target modules。算法精确为：

1. 将 root module 映射到 repository 内唯一 `module.py` 或 `module/__init__.py`；不存在/二义即失败；
2. 对每个 included module 加入从 `app` 到 module parent 的所有现存 `__init__.py`；
3. 解析每个 included `.py` 的全部 `ast.Import` 与 `ast.ImportFrom`，包括 function、conditional 和
   `TYPE_CHECKING` block 内 imports；
4. 对 relative import 按当前 package 解析 absolute name；越出 `app` 即失败；
5. 对每个 `from app.x import y` 同时尝试并包含 `app.x` package/module 与可解析的 `app.x.y` submodule；若 `y`
   只是 attribute，不产生额外 module，但 base module 必须存在；
6. 对每个可映射到 repository 的 `app.*` module重复 1-5，直到 fixed point；
7. 任一 unresolved `app.*` import 或 `from ... import *` 直接失败；closure 内出现任何 `import importlib`、
   `from importlib ...`、`import pkgutil`、`from pkgutil ...`，或 callee syntax exact 为 `__import__`、`eval`、`exec`
   的 `ast.Call` 也直接 `dependency_closure_unresolved`，不得 alias/手工 ignore；
8. External packages 不进入 path closure，按 Section 11 的 exact installed distribution versions 绑定；
9. 输出按 repository-relative path Unicode code point ASC 的完整 records：

```text
{repository_relative_path, exact_file_sha256}
```

`accepted_dependency_closure_sha256` 是该完整 array canonical SHA-256。Manifest 保存 algorithm version、exact root
modules、完整 ordered records 与 closure hash；所有 run artifacts 保存相同 closure hash。Verifier 必须从当前 bytes
重建 closure，要求 paths 和每个 hash exact equality，不能只比较预先列出的 root files。

对 G1 baseline `f40c5c84c3248639aa6603d43b6b306ad76d66fd` 的独立 dry-run closure 结果固定为 63 paths，包含
`app/models/**` initializer closure 以及 `query_rewrite.py`、`llm_query_rewrite.py`、`rerank.py`。Manifest 另存
`accepted_dependency_closure_path_count=63`；G2 approval 前后若重算不是 63，必须重新人工复核，不能更新 expected
count 继续。

G3 runner 另拥有 Section 4 exact evaluation path list；untracked/missing/dirty allowlisted evaluation path、dependency
closure drift、specification tree drift 或 path-list mismatch 一律 fail closed。

Task 6 必须在 calibration 前创建一个只含 Section 4 non-artifact code/data/tests/docs 的 G3 feasibility implementation
commit。Gold/cases/conformance/manifest 和所有 evaluator code 必须已 tracked 且 clean；calibration 记录完整 40 位 commit。
从 calibration 开始到 release evidence 完成，不得再修改或提交 code、dataset、config、controls 或 tests。Results、
policy、release evidence 是 phase outputs，不进入 code identity，也不能掩盖其余 allowlisted path drift。

Corrective overlay 进一步要求：`4217498277706ceb1ee2b60d25d593cbc80ef45f` 是 incomplete implementation identity，
不得被 replacement artifact 继承。新的 implementation commit 必须在 replacement calibration 前一次性包含并测试
`freeze-policy`、`verify-policy`、`post-freeze`、`assemble-release-evidence`、`verify-release` 及其所有 strict

Category array 必须按上述 enum order 保存，并且必须 exact equal loader 重算结果。固定 helper definitions：

```text
m = normalize_graph_name_v1(mention.text)
c = normalized_name of the linkable gold Entity
scoped = healthy publication Entity candidates after optional type hard filter
exact_matches = scoped Entities whose normalized_name == m
lexical_candidates = scoped Entities scored by lexical_score_v1 when exact_matches is empty
presented = lexical_candidates with score_micros >= 500000 in stable order
compact(s) = remove all whitespace code points from s
tokens(s) = whitespace-split normalized string, preserving order
```

Loader 必须先验证 gold references/scope，再重算以下 mention-level predicates。Case-level category 在任一 mention
predicate true 时为 true；utility predicates 单独按 case gold 计算。

1. `exact-canonical`
   - `gold_status='linkable'`；
   - `len(exact_matches)==1` 且唯一 row 是 gold Entity；
   - `m == c`；
   - `is_exact_control` 必须为 true，当且仅当本 predicate true。

2. `case-whitespace-normalization`
   - `exact-canonical` true；
   - raw `mention.text != gold.canonical_name`；
   - 两者经现有 normalizer 后相等。因为 v1 normalizer 只 trim/casefold/collapse whitespace，不允许其他 rewrite。

3. `prefix-suffix-omission`
   - `gold_status='linkable'`、`m != c`、`len(m)>=2` code points；
   - exact implementation condition 为
     `(c.startswith(m) or c.endswith(m)) and len(m) < len(c)`；
   - exact match 必须为空。

4. `abbreviation-like-overlap`
   - `gold_status='linkable'`、exact match 为空、prefix/suffix predicate false；
   - 令 `mc=compact(m)`、`cc=compact(c)`；`2 <= len(mc) < len(cc)`；
   - 以下二者之一为 true：
     - initialism：`len(tokens(c))>=2` 且 `mc` 等于每个 canonical token 首 code point 顺序连接；
     - strict subsequence：`mc` 是 `cc` 的 ordered code-point subsequence、`mc not in cc`，且
       `4 * len(mc) <= 3 * len(cc)`；
   - subsequence existence 用从左到右 greedy index scan；不允许 locale/transliteration/pinyin。

5. `word-order-token-overlap`
   - `gold_status='linkable'`、exact match 为空；
   - mention/canonical token sequence 都至少 2 tokens；
   - 两个 token multisets exact equal，但 ordered sequences 不相等；
   - prefix/suffix 与 abbreviation predicates 必须 false。

6. `close-name-negative`
   - `gold_status='unlinkable'`、`exact_matches` 为空；
   - `len(presented)>=1`，即至少一个同 scope candidate 达到固定 presentation floor；
   - `negative_entity_keys` 为空，避免把 scope negative 计入 lexical close-name population。

7. `same-score-ambiguity`
   - `gold_status='ambiguous'`、`exact_matches` 为空；
   - `len(presented)>=2`；
   - presented top1/top2 的 `score_micros` exact equal；
   - `gold_ambiguous_entity_keys` 必须等于所有并列 top-score Entity logical keys 的 stable ordered list。

8. `same-name-cross-type-ambiguity`
   - `gold_status='ambiguous'`、`entity_type_key=null`；
   - `len(exact_matches)>=2`，且 exact matches 至少两个 distinct Entity Type keys；
   - `gold_ambiguous_entity_keys` exact equal all exact matches in stable order；
   - `is_exact_control=false`。

9. `unpublished-cross-scope`
   - `gold_status='unlinkable'` 且 `negative_entity_keys` 非空；
   - 每个 referenced Entity 都满足 optional type filter，并且其 normalized canonical name exact equal `m`；
   - 每个 referenced Entity 必须在另一 Library/Ontology，或不属于 current publication Entity items；
   - referenced Entity 不能出现在 `exact_matches`、`presented`、selected 或 returned candidate list。

10. `not-found`
    - `gold_status='unlinkable'`；
    - `exact_matches` 与 `presented` 都为空。

11. `one-hop-evidence-utility`
    - `gold_utility.hop==1`；
    - Evidence/Relation/Node gold arrays 都非空且在 scoped healthy publication 可解析。

12. `two-hop-evidence-utility`
    - 与上一项相同，但 `gold_utility.hop==2`，且至少一个 gold Relation 只能从任一 seed 经恰好 2 hops 到达。

Overlap 规则也是合同：

- `categories` 是所有 true predicates 的完整集合，不允许只选一个 primary label；

## 12. Metrics 与 Numerator/Denominator

所有 rate 保存 nonnegative integer `numerator/denominator` 和 `value_micros: integer|null`。Denominator 为 0 时
numerator 必须为 0、`value_micros=null` 且 required gate fail；denominator >0 时 value 必须是 integer micros，不能
为 null 或记 float。

### 12.1 Intrinsic metrics

| Metric | Numerator | Denominator |
|---|---|---|
| auto-link precision | correct auto-linked mentions | all auto-linked mentions |
| link recall | correct auto-linked linkable mentions | all linkable mentions |
| non-exact link recall | correct auto-linked non-exact mentions | all non-exact linkable mentions |
| candidate Recall@5 | linkable mentions whose gold is selected or in first five candidates | all linkable mentions |
| abstention accuracy | ambiguous/unlinkable mentions not auto-linked | all ambiguous/unlinkable mentions |
| exact regression accuracy | exact controls linked to gold | all exact controls |
| scope safety | scope-negative cases with required fail-closed result | all scope-negative cases |
| determinism | repeated logical outputs equal first hash | all required repeat comparisons |
| property privacy | scanned forbidden marker surfaces with zero marker | all scanner surfaces |

另外记录 integer `wrong_auto_link_count`、`false_auto_link_on_unlinkable_count`、`publication_membership_failures`、
`privacy_leak_count`，全部 ceiling 0。

### 12.2 Utility metrics

每个 release question 先生成最多 10 个 Evidence logical IDs。Candidate required-mention failure时 set 为空。

```text
recall_q_micros:
  integer-half-up(|returned ∩ gold| / |gold|)

precision_q_micros:
  integer-half-up(|returned ∩ gold| / |returned|), or 0 when returned is empty

complete_q:
  1 iff gold subset of returned, else 0

any_q:
  1 iff returned intersects gold, else 0
```

Aggregate artifacts 保存：

| Metric | Numerator | Denominator |
|---|---:|---:|
| Evidence Recall@10 | sum recall_q_micros | question_count * 1,000,000 |
| Evidence Precision@10 | sum precision_q_micros | question_count * 1,000,000 |
| complete support-set coverage | sum complete_q | question_count |
| question with any gold Evidence | sum any_q | question_count |

Dense、hybrid、candidate 分别记录，不丢弃失败 question。Gain 使用 aggregate `value_micros` 的 exact subtraction。
Supplementary relation/node recall 使用相同 per-question macro-micros 规则，不作为 old retrieval 假 Relation ID。

### 12.3 Performance metrics

所有 duration 用 `perf_counter_ns`，artifact 保存 integer microseconds。30 个 measured samples排序；p50 index 为
zero-based 14，p95 index 为 zero-based 28，另存 max。Warm-up 5 次不进入 sample。记录 SQL statement count、Entity

## 13. Threshold Calibration 与 Bootstrap

### 13.1 Fixed threshold grid

只允许 Cartesian product：

```text
min_score_micros:
  850000, 880000, 900000, 920000, 950000

min_margin_micros:
  80000, 100000, 120000, 150000, 200000

candidate_floor_micros:
  500000 fixed
```

Calibration selection：先排除任一 wrong link、scope/exact/privacy hard failure，再排除 precision <1.0 或 unlinkable
false link；剩余组合最大化 non-exact correct auto-link count；tie 依次取更高 min score、更高 min margin。无组合则
G3 NO-GO，不扩大 grid。

### 13.2 Bootstrap pre-registration

只对 release split 的 per-question Evidence Recall@10 做 paired stratified bootstrap：

```text
algorithm_version = paired-stratified-bootstrap-v1
PRNG = Python random.Random / MT19937
seed = 2026071707
replicates = 10000
strata =
  one-hop-cjk
  one-hop-latin-mixed
  two-hop-cjk
  two-hop-latin-mixed
statistic = mean(candidate recall_q_micros - fixed best-control recall_q_micros)
```

Best control 按 release aggregate Evidence Recall@10 在 dense/hybrid 中选一次，tie 选 dense；不能每题 oracle 选择。
每个 replicate 在各 stratum 内按原 stratum size有放回采样，再按原 size加权合并。所有差值用 integer micros/Fraction；
排序 10,000 个 exact statistics，95% percentile CI lower 使用 zero-based index 249，upper 使用 index 9749。
令 frozen stratum 顺序为上表顺序、`d[h][i]` 为 manifest case order 的 paired integer-micros difference、`n_h` 为
stratum size、`N=sum(n_h)`。Point estimate exact 为 `Fraction(sum_h(sum_i(d[h][i])), N)`。每个 replicate 按 replicate
index outer loop、stratum order middle loop、draw index `0..n_h-1` inner loop，调用唯一 RNG 的
`rng.randrange(n_h)` 一次选择一个 index；statistic exact 为 `Fraction(sum_h(sum_draw(d[h][chosen])), N)`。禁止
`choices`、重新 seed、每 stratum 独立 RNG 或排序 input cases。
Unresampled point estimate 和每个 replicate statistic 都必须直接构造并约分为 Section 15.0
`ReducedRationalRecord`，不允许转 float 或 integer micros。`replicate_statistics_sha256` 对 replicate index `0..9999`
顺序的 10,000 个 reduced-rational objects canonical array 计算；artifact 不保存该大数组，verifier 必须从 dataset、seed
和 algorithm 重算 hash。GO 直接比较 lower record 的 exact rational value 与 `0/1`，由于 denominator 恒正，等价于
`ci_lower_micros.numerator > 0`。Seed、replicate、strata、ordering 或 percentile index 不得在 G3 更改。

## 14. GO / NO-GO 逐次 AND Gate

每个 post-freeze run 必须独立满足 Master Design Section 20 全部阈值；不得用三次均值掩盖失败：

```text

auto-link precision = 1.000000
exact regression accuracy = 1.000000
scope safety = 1.000000
privacy = 1.000000 and leak count = 0
publication membership failures = 0
false auto-links on ambiguous/unlinkable = 0
candidate Recall@5 >= 0.98
overall link recall >= 0.75
non-exact link recall >= 0.60
link recall gain vs exact-only >= 0.20
abstention accuracy >= 0.98
Evidence Recall@10 gain vs old_retrieval_best >= 0.10
complete support coverage gain >= 0.10
Evidence Precision@10 regression >= -0.05
question-with-any-gold gain >= 0.08
bootstrap 95% CI lower > 0
linker p95 <= 500 ms
link+graph p95 <= 1500 ms
link+graph p95 <= 1.25x faster old control p95
timeouts = 0
SQL statements <= 7
per-mention SQL = 0
projection rows <= publication entity_count <= 10000
```

三次 run 还必须具有相同 candidate canonical response-set hash、policy、dataset、code、environment 和 control
identities。一个 run 的 missing/skipped/null metric 即整体 NO-GO。

除 `bootstrap-ci-lower` 使用 Section 13.2 exact rational `> 0/1` 外，所有 threshold comparison 使用 integer micros，
不解析 decimal float：

```text

+0.20 = +200000
```

```text

```
