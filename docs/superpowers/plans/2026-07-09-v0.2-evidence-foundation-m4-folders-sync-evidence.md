# v0.2 Evidence Foundation M4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add M4 folders, sync source APIs, sync document operations, and evidence/source read APIs on top of the M2/M3 revision foundation.

**Architecture:** Add focused M4 schema, service, and router modules rather than expanding `app/api/documents.py`. Folder movement updates organization fields only. Sync document upsert/delete uses `(library_id, sync_source_id, external_id)` identity and reuses the existing revision/evidence generation path. Evidence/source reads are revision-aware and default to the current ready revision unless an explicit historical `revision_id` is supplied.

**Tech Stack:** FastAPI, Pydantic v2, SQLAlchemy async ORM, existing `require_lib()` permission dependencies, existing `ingest_service.reingest_document()` and `create_evidence_generation()` revision writer.

## Global Constraints

- Scope is v0.2 M4 only: folders, sync_sources, sync upsert/delete/sync, evidence/source read APIs.
- Do not implement UI, graph/entity/relation/ontology, connector workers, bidirectional sync, folder ACL, document ACL, or evidence ACL.
- Keep old document/source APIs compatible.
- New sync document identity is `(library_id, sync_source_id, external_id)`.
- Folder movement must not create a document revision.
- Folder movement must reject moving a folder under itself or any descendant.
- Deleted or disabled sync sources must reject upsert.
- Sync upsert/delete must be idempotent.
- Batch sync must support partial success with independent item error reporting.
- Evidence/source APIs must enforce library read permission through `require_lib("read")`.
- Evidence/source APIs default to current ready revision and require explicit `revision_id` for historical evidence.
- Follow TDD: write a failing test, run it red, implement the minimal code, run it green before moving to the next behavior.

- [ ] **Step 3: Implement sync upsert/delete**

For upsert:
- Validate `metadata` with `validate_external_metadata`.
- Resolve active sync source and reject deleted/disabled sources with `409`.
- Resolve or create `folder_path`.
- Query existing document by `library_id`, `sync_source_id`, `external_id`, and `deleted_at IS NULL`.
- If no document exists, create a `Document` with `sync_source_id`, `external_id`, folder, metadata, visibility/security, `current_revision=1`, `status="pending"`, split text, and call `create_evidence_generation`.
- If document exists and content/title/metadata/visibility/security are unchanged, update folder only and return `operation="unchanged"` without creating a revision.
- If revision-affecting fields changed, update visibility/security/folder then call `ingest_service.reingest_document`.

For delete:
- Query by sync identity.
- If missing, return `operation="not_found"`.
- If present, set `deleted_at`, `status="deleted"`, supersede active jobs, enqueue cleanup, and return `operation="deleted"`.
