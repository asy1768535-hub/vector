# v0.2 Evidence Foundation M3 Worker Publication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make v0.2 evidence revisions become ordinary-retrieval current revisions only after revision-scoped Qdrant upsert succeeds and a database CAS publish succeeds.

**Architecture:** Keep the legacy integer revision worker path available by default. Add feature-flagged revision-ID worker and visibility paths that process `embedding_jobs.document_revision_id`, build revision-aware Qdrant payloads and deterministic point IDs, then publish `documents.current_revision_id` only in a short transaction after Qdrant upsert. Move revision cleanup to post-publish and revision-ID-targeted outbox events so cleanup cannot delete the still-current revision.

**Tech Stack:** Python 3.10+, FastAPI settings via pydantic-settings, SQLAlchemy 2.0 async ORM, Qdrant HTTP API, pytest.

## Global Constraints

- M3 scope only: worker eligibility, Qdrant payload/point IDs, CAS publication, ordinary retrieval visibility, and revision-safe cleanup.
- Keep legacy worker and retrieval behavior unchanged unless the new M3 feature flags are enabled.
- `ENABLE_REVISION_ID_WORKER` default is `False`.
- `ENABLE_REVISION_ID_VISIBILITY` default is `False`.
- Do not add graph, ontology, entity, relation, folder API, sync API, or evidence read API behavior.
- Do not publish `documents.current_revision_id` before Qdrant upsert has succeeded.
- Worker must not hold a document row lock while embedding or Qdrant upsert runs.
- Use TDD: add the failing test first, run it red, implement minimal code, run it green.
- Existing dirty chat files in the main checkout are unrelated and must not be touched.

- `app/services/keyword_search.py`: include `document_revision_id` in keyword payloads and restrict keyword recall to current revision when revision-ID visibility is enabled.
- `app/services/qdrant.py`: add deletion by `document_revision_id`.
- `app/services/cleanup.py`: add revision-scoped cleanup enqueue and dispatch functions.
- `app/models/cleanup_outbox.py`: add event constants for revision-scoped cleanup events.
- `app/services/ingest.py`: skip pre-publication integer cleanup for evidence writes when revision-ID worker is enabled; publication will enqueue cleanup after CAS.

Do not modify:

- Alembic migrations. The existing `qdrant_cleanup_outbox.payload` JSONB column can carry `document_revision_id`.
- UI files.
- Chat API or chat tests.
