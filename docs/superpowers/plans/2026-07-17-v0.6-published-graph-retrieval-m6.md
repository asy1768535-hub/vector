## 1. Goal And Decision Semantics

M6 closes v0.6 with reproducible release evidence rather than another runtime feature:

```text

```

`PASSED` means every hard gate in this plan passed on one recorded workspace boundary. It means the v0.6 code is
releasable with the feature still disabled by default. It does not enable a Library, deploy configuration, migrate data,
publish a graph, or start v0.7 work.

`BLOCKED` is mandatory when any hard gate fails or is not run. Local offline success, a previous calibration, an average
across post-freeze runs, or a full suite that skipped the mandatory PostgreSQL files cannot be relabeled as release
acceptance.

## 5. Invalidation And Escalation Rules

M6 is an acceptance phase, not a repair phase. Apply these rules before any edit:

- a documentation-test or report-format defect may be fixed inside the M6 file boundary;
- a failure caused by an existing M1-M5 runtime/query/API behavior blocks M6 and requires a separately reviewed fix;
- any fix to a path included in `scripts/graph_retrieval_eval.py::IMPLEMENTATION_PATHS` changes the implementation-tree
  identity and invalidates the frozen policy and all three post-freeze runs;
- any dataset, manifest, evaluation config, normalization, response canonicalization, privacy policy or threshold change
  requires a new calibration, new policy version and three new post-freeze runs;
- an artifact is immutable: never overwrite, amend, reformat or line-ending-normalize an accepted JSON/JSONL file;
- a slower or failing M6 environment does not authorize selecting a different earlier run or averaging results;
- no failure authorizes a timeout increase, new index, Migration `0024`, fallback read, properties exposure or old-path
  behavior change.

When any invalidating condition occurs, write a `BLOCKED` report with the failing command and stop. Return to M5 planning
before changing code or release evidence.
