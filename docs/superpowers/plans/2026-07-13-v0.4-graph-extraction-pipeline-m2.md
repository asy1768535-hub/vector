# v0.4 Graph Extraction Pipeline M2 Implementation Plan

> **Status:** Approved for inline execution after M1 acceptance on 2026-07-13.
>
> **Authority:** `2026-07-10-v0.4-graph-extraction-pipeline.md`, the completed M1 plan, the v0.3 graph
> specification, and the v0.2 evidence specification, in that order.

## Goal

Implement only the deterministic extraction boundary used by later workers:

```text
Evidence-backed Unit
-> immutable Context Snapshot
-> injection-resistant Prompt
-> DashScope OpenAI-compatible request
-> strict JSON/Pydantic parse
-> fenced Attempt result record
```

M2 does not claim Units, poll queues, create Jobs, create Candidate/Occurrence rows, bind model quotes to Evidence,
aggregate candidates, validate graph schema, materialize graph facts, expose public extraction APIs, trigger extraction,
or create Migration `0022`.

## Frozen Interfaces

### Strict Output Contract

Create `app/schemas/graph_extraction.py` with:

```python
ExtractionEvidenceClaim(context_ref, quote)
ExtractedEntityPayload(local_id, name, entity_type_key, aliases, properties,
                       external_mapping_hints, confidence, evidence)
ExtractedRelationPayload(source_local_id, relation_type_key, target_local_id,
                         properties, confidence, evidence)
GraphExtractionPayload(entities, relations)
```

All models use `extra="forbid"`. `GraphExtractionPayload` rejects duplicate Entity `local_id` values and any Relation
endpoint not declared in the same payload. Empty `entities` and `relations` arrays are valid.

### Parser

Create `app/services/graph_extraction_parser.py`:

```python
parse_graph_extraction_output(raw_content: str) -> GraphExtractionPayload
```

The Parser may remove exactly one outer JSON Markdown fence only when the entire response is fenced. It must not
search prose for JSON, repair JSON, concatenate fragments, ignore extra fields, or trust model-provided UUID/span
fields. Errors are classified as `invalid_json` or `invalid_schema`; persisted error text is sanitized and bounded.

### Prompt

Create `app/services/graph_extraction_prompt.py` with a versioned system prompt and:

```python
graph_extraction_prompt_hash() -> str
build_graph_extraction_messages(*, context_text: str, ontology_snapshot: dict) -> list[dict[str, str]]
```

The system prompt treats document content as untrusted data, forbids tool/command execution and unsupported
inference, restricts types to the frozen ontology, requires verbatim quotes and server context refs, forbids database
IDs/spans/reasoning, and requires JSON only. Prompt content is deterministic and SHA-256 traceable.

### Provider Adapter

Create `app/services/graph_extraction_provider.py`:

```python
DashScopeGraphExtractor.extract(...) -> ProviderResponse
MockGraphExtractor.extract(...) -> ProviderResponse
```

The production adapter posts to `{base_url}/chat/completions` with Bearer auth, `temperature=0`, non-streaming mode,
and `response_format={"type":"json_object"}`. The API key is accepted only at the HTTP boundary and never appears in
payload hashes, logs, exceptions, or returned records. Provider failures are categorized as timeout, network, or HTTP;
HTTP bodies are sanitized and bounded. The mock adapter is deterministic and performs no network access.

### Context Builder

Create `app/services/graph_extraction_context.py`:

```python
build_context_snapshot(db, *, job, unit, previous_chunks, next_chunks,
                       max_context_chars) -> ExtractionContextSnapshot
```

Rules:

1. Job, Unit, Document, Revision, Chunk, and Evidence must share library/document/revision scope.
2. The center Chunk must match `unit.center_chunk_id`; its deterministic primary Evidence must match
   `unit.center_evidence_id`.
3. Primary Evidence is a valid active `Chunk.evidence_id`, otherwise the first active `chunk_evidence` by `seq`.
4. Every selected ref stores all active same-scope Evidence IDs, not only the primary ID.
5. `effective_title_path` uses Chunk, direct Block, then primary `chunk_blocks` Block, then `[]`.
6. Neighbors are same-revision, same-effective-title-path Chunks selected stably by `seq`; `p1`/`n1` are nearest.
7. `c0` text is never truncated. Budget pressure removes farthest neighbors first, then document metadata. If the
   current context still exceeds the budget, fail before any Provider call.
8. Title, title path, positions, metadata, and ontology are context only; only Chunk refs enter `context_mapping`.
9. Snapshot payload and hashes are deterministic. Existing non-purged one-to-one snapshots are returned idempotently;
   purged snapshots are not silently rebuilt for the same Unit.
10. Context text is never logged.

### Attempt Recording

Create `app/services/graph_extraction_attempts.py`:

```python
create_pending_attempt(db, *, unit_id, context_snapshot_id, claim_token,
                       request_payload_hash, max_attempts) -> ExtractionRawOutputAttempt
finalize_attempt(db, *, attempt_id, claim_token, completion) -> bool
```

`create_pending_attempt` locks the Unit, verifies processing state, token, unexpired lease, and attempt budget, allocates
an immutable next `attempt_no`, inserts a pending Attempt, increments `model_attempt_count`, and commits in one short
transaction. `finalize_attempt` updates only a pending Attempt whose Unit still has the same live claim. A lost lease
returns `False` and discards the caller's in-memory Provider result. Terminal Attempt rows cannot be updated again.
M2 does not implement the Unit claimer or stale Attempt reclaimer.

## Definition Of Done

- Strict payload parsing enforces all Unit-level protocol rules.
- Prompt is injection-resistant and hash-stable.
- Provider adapter is OpenAI-compatible, categorized, sanitized, and secret-safe.
- Context snapshots are Evidence-rooted, deterministic, immutable, budgeted, and same-scope.
- Attempt creation/finalization is short-transaction and fenced.
- No external HTTP call occurs while a database transaction or row lock is held by M2 code.
- M1/v0.3/full regressions and Ruff pass.
- M2 completion is recorded before M3 planning begins.
