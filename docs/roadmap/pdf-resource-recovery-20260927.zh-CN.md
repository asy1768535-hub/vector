# PDF 资源超限恢复

状态：开发与验证中，尚未声明恢复成功。

目标：恢复已授权批次内因 OCR 页数、渲染像素及总页数预算失败的文件。
保留原始文件、文档归属、原始页码；完整解析后沿用既有入库和向量化链路。

实现边界：解析 owner 为 `pdf_extract` 及同目录的批处理辅助模块；
`import_parsing` 只传入配置，Worker、存储与向量 schema 保持既有契约。
新增 `PDF_RESOURCE_RECOVERY_ENABLED=false`，只在专用恢复进程启用。
分批最多 25 页，每批继续遵守 OCR 页数和图像预算；整文档仍有页数、
文本及 OCR 块总预算。超大页自适应降低渲染 DPI，最低 72，不能满足时明确失败。
不跳过失败页，不凭空修正数字，不切换远程模型。局部页批次不作为独立文档入库。

验证：真实 PDF 生成的跨批次页序/定位测试；超大页实际渲染预算；空白批次、
中途失败及全局预算负向测试；原路径回归。每类一份失败原件通过实际解析、
页覆盖检查及关键区域抽查后再推进余下同类文件。数据库 ready 与当前版本
embedding done 才算成功，必要时核对当前版本 Qdrant 点。

发布：以运行镜像为基础构建仅含本次补丁的独立恢复镜像，记录文件哈希。
生产源码、任务清单、源文件检查证据留在授权服务器内。只重试精确失败快照，
串行启动验证；保留原服务。回退为停止专用恢复进程，保留已成功文档，核实在途
任务后按既有重试契约恢复。用户已授权处理这批失败文件；不恢复定时自动化。
