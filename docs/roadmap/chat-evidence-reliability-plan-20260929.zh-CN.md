## 阶段目标与用户流程

用户在自己有读取权限的知识库中，指定两份文件并提出逐项对照、表格汇总或状态判断问题。系统依次完成文件定位、相关片段检索、必要的表格行补齐、来源绑定和回答生成。

用户最终应看到：

1. 两份指定文件分别有哪些记载，差异对应哪个字段及引用。
2. PDF 引用显示可信的物理页范围；Excel 显示工作表及行范围。印刷页码与 PDF 物理页码有差异时分别说明。
3. 文件未唯一确定、证据缺失、表格范围未覆盖或文字不可辨时，指出具体缺口。
4. 历史事实、材料中的可能性与当前状态分开表述。

首个可用结果是：指定文件不再被其他相关报告挤出本次证据；同一表格所需行在既定预算内被补齐。成功标准是减少真实问答错误，不追求所有问题都有确定答案。

实施主线为：**建立通用的文件范围取证、结构组补齐、引用绑定和回答约束，再用原失败题及独立同类样本验证。** 历史会话页码补显属于辅助增强，不能拖延这条主线，也不能代替真实回答收益。现有材料足够的对照题，改成统一“无法确认”不算修复。

### 适用的问题类型

| 问题类型 | 通用处理方法 | 边界及成功标准 |
| --- | --- | --- |
| 明确指定文件的跨文件比较 | 在权限范围内解析文件名称及无歧义简称，分别限定文件检索，保留每份文件的必要证据 | 换文件名、文件顺序和比较对象仍有效；不能用其他相关报告替代指定文件 |
| 未明确指定文件的主题问题 | 保留现有全库检索，按来源组织证据；若问题要求穷举或完整对照，先建立能被证明的文件/表格范围，必要时只澄清范围 | 不把主题 Top-K 当成全库穷举；仅未检索到不能推出库中不存在 |
| 表格明细、分组计数和合计 | 在命中的结构组内补齐相关连续行、保留表头和单位；确认覆盖范围后计数或计算，计算按可验证数值执行 | 表格拆片、目标行在中间或边界也能处理；行范围断裂或超限时不输出完整合计 |
| 文件、页码及引用错配 | 来源编号绑定服务端可信文件身份、revision、位置；上下文按来源明确分组，正文断言与引用分别核对 | 近似文件名、相同正文和不同 revision 不互相冒充；有效引用编号不等于断言正确 |
| 同名对象或相近字段混淆 | 保留字段表头、对象、单位和上下文，对照相同字段，不以语义相似的另一个编号或另一资产替代 | 更换字段名称和业务领域仍能区分；表格结构或 OCR 含混时只限定对应项 |
| 历史、不确定及相互冲突材料 | 保留事件时间、材料时间、对象和限定词；有冲突时分别列出出处，缺当前证据时不升级为当前事实 | 覆盖“可能/初步/据称”、旧记录、后续变更及不同对象限制，不只针对某一种资产 |

第一版优先复用当前已保存的结构定位。XLSX 有工作表/行范围时可提供组补齐；DOCX/PDF 若已有可信结构组与位置则采用同一组契约。没有可靠表格结构的扫描 PDF，不靠 seq 邻近或正文拼接宣称完整恢复；记为输入结构能力限制，另行定位解析环节。不同格式适用能力必须在验收中逐项说明。

## 范围与非目标

### 第一版最小方案

**指定文件定位与分别检索。** 优先解析用户明确给出的文件名，匹配当前库及文件夹可见范围中的文档。规范化空格、标点和扩展名，不硬编码样本文件名或业务别名。简写只有在现有标题中能唯一、明确匹配时才自动采用；存在重名或歧义时请求用户明确文件，不能静默换成相关报告。S1 必须先冻结文件定位算法及输入输出，并覆盖完整名称、原问题简称、乱序标题词、重名和近似但无关标题；不能只在诊断中传入正确 ID 就宣称自动定位通过。若既有目录能唯一确定指定文件，不能通过反复要求用户重写问题隐藏定位失败。每份指定文件单独限定 document_id 检索，再合并证据，避免被其他文件的高分片段挤出。

**表格补齐。** 命中 XLSX 后，优先使用同 revision、同原始表格组的 `parent_unit_id`，结合工作表及行范围加载相关已有 chunks。元数据缺失时保留证据不完整，不默认扩大成整份文件。补齐不依赖全局重排前五位；必要组及每份指定文档先保留预算，再放其他可选片段。不得把必要组补入候选后又按原 Top-K 裁掉，也不得以“某个分片编号在 used_records 中”冒充该分片全文已进入模型；必须检查实际上下文的内容哈希或完整范围。展示时按原行顺序保留表头、行范围和来源。连续行覆盖不等于已证明所有业务对象都存在，模型仍须依据实际行作答。

**预算及缺口处理。** S0 在看到候选结果前冻结以下第一版建议上限：最多 3 份指定文件、每个表格组最多补齐 8 个 chunks、本次最多 20 个证据片段、总字符不超过当前 12,000 字预算。文件检索调用最多每文件一次，不增加循环检索、自动重试或第二次模型验证。若现有配置更严格，使用更严格的值。超限时显式报告未覆盖范围，不能输出完整核对或完整合计结论；预算变化必须在结果前记录原因。

**问题所需覆盖与计数/计算。** 取证应区分局部事实提取和要求完整范围的比较、计数、合计、否定判断。完整性建立在已确定的文件及结构组、行范围和实际入模内容上，不建立在片段相似度上。优先复用已有结构化数值及计算能力；可明确解析的数字先确认字段、单位、去重与覆盖范围，再按确定性方法计算。无法可靠解析的表格不强算。这个契约适用于新文件和新题目，不将已知样本的楼号、行数、页码或答案写成规则。

**引用身份与位置。** 可信来源应绑定 document_id、当前 revision、chunk_id、文件标题和位置；PDF 页范围与 Excel 工作表/行范围分类型展示。拒绝非法页码、逆序范围或与身份不符的定位。页码缺失时显示未提供位置，不扫描正文中任意“第 N 页”去猜元数据。补齐片段注明取证来源为表格扩展，不虚构 rerank 分数。

**历史兼容。** 核心修复首先保持既有历史来源和回答含义，不为通过验收修改旧回答。新增实时定位字段为可选字段，不丢失原有标题/身份。历史页码增强是可单独延期的辅助项：先核查现有来源快照/元数据能否安全复用；按绑定 chunk 与 revision 读取历史定位时，验证身份和文本哈希，并重新检查权限。不能用当前 revision 的页码冒充旧回答来源；无法恢复则显示“历史定位未保存”。本版不默认增加表或迁移；若辅助增强必须新增持久化结构，延期该增强，核心检索修复继续按原范围验证。

**回答约束及检查。** 对照题按文件分别列示原文记载，再比较同名字段；字段缺失、表格错位或 OCR 含混时说明不确定。保留“可能”等措辞，区分事件时间与当前状态、区分限制条件适用的资产。程序校验引用编号是否合法、是否映射本次来源，并维护系统生成的权威来源列表。文件归属、字段和时态的语义正确性须通过真实样本验收；有效引用编号不能证明整个断言有依据。必须同时检查回答正文中的文件归属，引用卡片显示正确而正文仍称错文件视为失败。第一版不建设通用事实验证引擎，不用关键词替换强行修正回答，不默认增加一次模型调用。

### 范围边界

- 复用当前原件、解析块、chunks、向量和已有证据定位，不 OCR、重解析、重新向量化或修改文档内容。
- 不硬编码文件名、页码、chunk 序号、登记编号、问题标准答案或知识库标识。
- 不顺带发布工作树中的 PDF 候选、权限、多库检索或其他任务改动。
- 不改变授权规则，不扩大跨库或跨文件夹可见范围。
- 不新增数据库表、人工审核平台、第三方上传、Agent 工具循环或定时任务。
- 本次交付规划及任务记录；实现、真实模型回放和本专项部署分别记录其授权与证据。此前其他专项发布授权不自动扩展到本专项。

## 测试、安全与影响

本轮文档交付采用 T0：读回、链接、结构及 diff 检查，不新增实现测试。后续指定文件定位、预算、权限、revision、引用位置等确定性行为按 T2 先复现失败，再最小实现；生成质量及真实浏览器/模型表现按 T3 使用可重复的实测路径。Mock 测试不能证明答案事实正确或生产生效。

拟改符号逐项 upstream impact；HIGH/CRITICAL 修改前报告调用方、执行流和风险，UNKNOWN 不当作安全。共用 `build_context` 或生成约束有必要修改时，补公开回答的相关回归；不能为了绕过共用 Owner 在多个入口复制同一语义。

拟复用的窄测试入口：

- `tests/test_chat_api.py`、`tests/test_chat_answer.py`：检索调用、资料上下文、来源及生成契约。
- `tests/test_chat_history_api.py`、`tests/test_chat_stream_cancellation.py`：历史来源、流式终止及落库行为。
- `tests/test_chat_graph_context.py`、`tests/test_chat_graph_augmentation.py`：新增普通来源不扰乱图谱引用编号。
- `tests/test_retrieval_filter.py`：指定文件过滤和可见性；若底层不修改，只选择被调用路径的相关用例。
- Chat/ChatLogs 的现有前端测试入口在 S0 用 `rg --files admin-ui` 确认后记录；不照搬其他页面的测试通过数。

必要负例包括：同名文件、简写歧义、无权限或已删除文件、文件夹外文档、旧 revision、缺失定位、断开的表格行、预算超限、两个不同编号字段、历史事件和当前状态、相同资产与不同资产限制、资料的“可能”与确定事实、来源正文中的诱导指令。合成数据不得包含真实业务原文或凭据。

权限沿用 Chat 的鉴权和库级读取。新增文件解析、表格查库和历史定位查询必须在相同授权范围内进行，不能信任客户端传来的标题、document_id、revision 或 chunk_id；不把隐藏文档的存在透露给无权用户。来源正文作为不可信资料，不执行其中指令。每次读取限定数量、字符和现有超时。

## 验证方法

### 真实样本及证据绑定

S0 在服务器现有私有范围保存最小样本清单：原件哈希、revision、问题哈希及审计记录、片段身份与文本哈希、期望证据范围、代码/模型/提示词版本、检索参数和执行时间。仓库只记录脱敏验收结果。旧审计缺失的中间结果保留不可追溯，不能用新诊断补写成历史事实。

Q6 所涉目标报告关键两页的原件表格仍需最小核对，区分真正的文件差异与 OCR 字段/数字错误。优先使用服务器既有证据；若需新取图，按既有图像授权边界一次性提出准确范围和位置。原件内容不确定时不冻结错误的标准答案，也不在本专项偷偷改解析器。

### 行为验收

验收分三层：**原失败题回归、独立同类能力、原正常能力不退化**。只通过原三道失败题，不能宣布这类问题已解决。

独立集在 S0 冻结，至少覆盖上表六类问题；采用项目既有公开/合成测试资料，真实材料仅在已有授权私有范围选取。实现过程中不读取独立集期望答案调规则。样本至少改变文件名、业务对象、字段、单位、时间条件和切片位置；不是把原题同义改写几遍。不得为验收下载新的业务原件或扩大第三方传输。

确定性门禁包括：完整文件名及简称唯一/歧义定位、指定文件均被保留、目标表格行位于拆片边界、结构组超过预算、字段/单位不同、不同 revision、引用编号与来源绑定，以及无指定文件的主题问题不误报全库完整性。所有必需确定性门禁必须通过。

真实生成按问题类型记录来源归属错误、字段错配、计算错误、时间/确定性升级、证据不足时虚构和有足够证据时错误拒答。独立集结果单列，不能和原题混在一起提高“通过率”；验收保留真实未解决项。样本量及模型调用预算在 S0 冻结，采用最小有代表性的输入组合，不为了扩充数字建立评测平台。

| 检查 | 通过标准 |
| --- | --- |
| 两道对照题取证 | Q5 必要表格四片 4/4、Q6 必要三片 3/3 完整进入模型；两份指定文件均覆盖且必要组不被再裁掉；仅增加来源条数或片段编号不算通过 |
| 原问题与简写 | 原问题原样回放；简称唯一时正确定位，歧义时明确询问；用完整文件名改写后的成功单独计数，不能冒充原问题已修复 |
| 来源与字段 | 回答正文、引用卡片、字段及每项数值与对应证据一致；产权编号不替代抵押登记编号；解析含混保留限定；明确可恢复的证据不被统一拒答掩盖 |
| 当前状态判断 | 历史扣划、可能性和资产限制各有对象及时间；没有当前材料时不输出确定的当前状态 |
| 四道回归对照 | 已核实的事实提取、计算和关键引用不退化；未知的原件一致性另列未验证 |
| 引用全链路 | 当前回答、流式返回、刷新历史及审计的来源身份一致；页/行范围可信，缺失信息明确 |
| 数据保持 | 原件、当前 revision、解析块、chunks 数量及文本哈希、对应向量身份/数量/哈希与基线一致；只允许正常新增问答审计记录 |
| 运行边界 | 权限负例拒绝；超限不假装完整；provider 异常不冒充资料不存在；其他检索调用方契约保持 |

原七题模型回归上限建议为 17 次：同一版本绑定的 7 次基线、7 次候选及三道失败题各一次复查。独立同类集在此之外单列预算，建议首批不超过 8 个生成用例，同时覆盖六类问题；以同版本基线/候选对照为主。两部分调用预算须在 S0 一并冻结，上限不是必须耗尽的次数，既有同版本证据可复用。新增失败才扩大验证，先记录原因。小批通过只支持已验证的问题类型和格式，不宣称所有问答都不会出错。

验收结论必须逐题给出“必要证据完整入模 / 正文与引用正确 / 有效字段核对 / 合理保留不确定 / 实际耗时”的结果。**文件已存在且证据可恢复，却仍回答未提供文件或无法核对，判为未修复。** Q6 的某项原件真值若尚未确认，只限定那一项，继续验收其他已确认字段与来源，不能据此停止整个检索修复。

记录每题检索耗时、首字时间、总耗时、来源数、实际入模字符量、模型及检索调用次数。建议性能门槛在 S0 预先冻结：受影响题新增检索耗时不超过 3 秒，正常单文件题不新增检索调用；超过门槛先缩小方案或说明收益/成本，不事后改门槛。本轮没有性能收益或额外耗时的已验证结果，小样本不报告具有统计意义的 p95。

### 检查命令与交付证据

文档：本地链接检查、结构检查及 `git diff --check`。实现时复用项目 `.venv/Scripts/python.exe -m pytest -q` 运行上述受影响测试；前端使用确认后的现有 Node 测试。提交或发布准备前按 AGENTS 执行图谱变更分析，partial/truncated 不视为干净结果。

验收报告必须分别写：本地确定性契约、真实检索、真实模型回答、浏览器引用、数据不变性和生产发布状态。依据 [验证矩阵](../quality/verification-matrix.md)，未实测平面标为未验证，不拿本地通过数代替生产结果。

### 发布与回退准备

验收通过后提取本专项精确文件、配置和测试范围；与当前生产版本重新核对，排除所有无关未提交改动。明确公开回答受影响范围、来源兼容行为、健康检查及回退版本，使用现有发布机制。当前仅编写规划，发布前须取得本专项部署授权。

部署后通过正式鉴权入口核对指定题和引用卡片，并核对文档、解析块、chunks 与向量未变化。来源错配、越权、正常题退化或资源预算异常时回退本专项版本；历史问答保留其原版本含义，不覆盖旧回答制造成功。

## 停止条件与未验证

以下情况停止当前实施步骤，先定位原因或调整明确范围：

- 原件/revision/证据哈希不符，或读取范围超出用户权限。
- 某项关键页文字/字段归属不能确认时，停止对该项真值的成功声明；继续处理已经能够验证的检索、来源和其他字段，不扩大为整项停工。
- 需要新增表、迁移、额外模型调用、改造全局检索或扩大取图才能推进。
- 预算不能覆盖完整对照，或者只靠调大 Top-K、邻居片段、提示词就宣称成功。
- 工作树出现其他任务对同一 Owner 的并行改动，无法安全区分发布内容。
- 同一根因连续三次修复未通过，停止叠加补丁，重新检查失败边界。

未验证项：原件关键表格真值、简写解析的通用准确性、独立同类样本收益、不同格式结构组支持程度、候选真实收益、历史定位的无迁移接入方式、真实浏览器卡片、额外耗时、模型输出稳定性及生产生效情况。S0 逐项补证据，不把这些写成已完成。

本轮 Git 边界：只新增本规划和本机任务记录，索引仅增加本规划入口；保留工作树已有修改，不暂存、不提交、不切换分支、不创建 worktree。后续若需隔离实现，遵循 AGENTS 的工作树授权规则。
