# 普通用户上传任务与文档上传人展示规划

> 状态：本地实施与定向验证已完成，待业务确认和提交  
> 确认日期：2026-09-03  
> 本文记录已确认范围与本地实施状态，不表示功能已经上线。

## 0. 本地实施状态

- 已完成独立的目录式“我的任务”页面、后端目录分页/概况/重试、中文失败说明，以及替换上传进入同一异步任务链；
- 已完成知识资产的上传人展示与筛选、普通用户邮箱脱敏、管理员完整邮箱，以及本人删除自己上传文档的服务端校验；
- 已完成桌面、390px 和 320px 本地界面检查，以及相关后端和前端定向测试；
- 尚待产品确认：当前实现要求成员仍具有该知识库的 `insert` 上传权限才能查看自己的历史任务。若只保留 `read` 阅读权限的成员也应查看历史任务，需要单独放宽该授权边界。

## 1. 目标

让普通用户能够：

- 在“我的任务”页面查看自己上传文件的处理情况和已生成的知识资产；
- 重试可以恢复的失败任务；
- 看到中文错误原因和下一步处理建议；
- 在“知识资产”中查看文件由谁上传，并按上传人和上传时间筛选；
- 删除自己误上传的文档，但不能借此删除其他人的文档。

管理员原有的全局任务监控、队列和 Worker 信息保持不变。

## 2. 已确认的产品决定

1. 将原“我的文件”导航改名为“我的任务”，保留原路由 `/knowledge-assets/my-files` 以兼容旧链接。
2. “导入与替换”只保留“新增数据”和“替换已有文档”；任务查询放在独立“我的任务”页面。
3. 普通用户只能查看和重试自己发起的任务。
4. 个人任务固定查看全部历史，不提供最近 30 天筛选。
5. 用户先选择知识库，再按上传时的文件夹路径查看该目录下的文件任务。
6. 任务目录默认每页 20 条，最多每页 50 条，必须使用后端分页。
7. 不提供取消任务功能。
8. 上传错误的文件可在“知识资产”中删除；本人可以删除自己上传的文档。
9. 普通用户优先看到上传人的姓名，邮箱只显示部分；管理员可以看到完整邮箱。
10. 知识资产筛选栏暂时只保留标题搜索、上传人和上传时间，其他分类以后按需要再增加。

## 3. 页面结构

### 3.1 导入与替换

页面顶部模式选择保持为：

```text
新增数据 | 替换已有文档
```

个人任务不再嵌入该页面。

### 3.2 我的任务目录

“我的任务”使用原“我的文件”的独立页面位置：

- 顶部选择一个当前用户仍具有上传权限的知识库，任务范围固定为全部历史；
- 左侧显示当前范围内由上传任务路径形成的根文件夹及任务文件数；
- 右侧显示当前目录的直接子文件夹和直接文件任务；
- 点击文件夹或面包屑时只请求目标目录，不在前端拉取全部任务后拼目录；
- 没有相对路径的单文件上传和替换任务显示在根目录；
- 已生成 `document_id` 的任务文件可直接打开对应知识资产详情。

### 3.3 我的任务列表

当前文件夹下的任务文件显示：

- 文件名；
- 所属知识库；
- 当前处理阶段；
- 处理进度；
- 任务状态；
- 提交时间；
- 中文失败原因；
- 可用操作。

面向普通用户的阶段名称统一为：

| 内部阶段 | 用户界面名称 |
|---|---|
| uploading | 正在上传 |
| queued | 等待处理 |
| converting / validating / parsing | 正在解析 |
| chunking | 正在生成知识片段 |
| embedding | 正在生成向量 |
| graph | 正在构建知识图谱 |
| completed | 已完成 |
| failed | 处理失败 |

普通用户界面不展示 Worker、内部队列、内部任务 ID、尝试次数、原始异常堆栈或系统级批量重试。

## 4. 任务刷新与性能

- 当前目录默认每页 20 项，可选择每页 20 或 50 项，子文件夹排在文件任务之前；
- 目录、文件任务和概况由后端分页、筛选和聚合，前端不得先拉取全部任务再计算；
- 同一时刻最多存在一轮列表或统计请求；
- 只有存在待处理或处理中任务时才自动刷新；
- 页面不可见、用户切换到其他模式或组件卸载后停止刷新；
- 刷新不得打断当前筛选条件、页码和用户正在查看的任务；
- 单次请求必须有明确上限，避免任务历史增长后拖慢前端。

## 5. 失败任务重试

“重试”只在任务确实可恢复且属于当前用户时显示。

### 5.1 可以直接重试

文件已经传到服务端，但解析、切分、向量化或后续处理失败时，用户点击“重试”后重新进入处理队列。

### 5.2 需要重新选择文件

文件传输本身失败时：

- 当前页面仍保留本地文件对象：允许重新上传；
- 页面刷新后浏览器不再持有本地文件：提示用户重新选择原文件。

### 5.3 不可重试

格式不支持、文件超过限制、权限不足等确定性错误不显示无效的重试按钮，而是显示对应处理建议。

服务端必须重新校验当前用户、知识库权限和任务归属。修改任务 ID 不得看到或重试其他用户的任务。

## 6. 错误信息中文化

底层稳定错误代码继续保留，避免破坏接口、测试、日志和管理员排错；普通用户界面将错误代码转换为中文说明。

| 错误类型示例 | 普通用户看到的内容 | 建议操作 |
|---|---|---|
| file_too_large | 文件超过知识库允许的大小 | 压缩或拆分后重新上传 |
| unsupported_type | 暂不支持此文件格式 | 转换为支持的格式后上传 |
| upload_incomplete | 文件上传不完整 | 重新选择并上传文件 |
| duplicate_file | 该文件已经上传 | 到知识资产中查看现有文件 |
| parse_failed | 文件内容解析失败 | 检查文件是否损坏后重试 |
| embedding_failed | 知识内容处理失败 | 稍后重试任务 |
| permission_denied | 没有向该知识库上传文件的权限 | 联系知识库管理员 |

普通用户只显示中文说明、建议操作和可用按钮。管理员任务详情可以同时显示中文说明与完整原始错误代码。

## 7. 知识资产筛选与上传人展示

知识资产筛选栏固定为：

```text
搜索文档标题 | 上传人 | 上传时间范围 | 筛选
```

本次移除：

- 文档状态；
- 分类状态；
- 分类标签。

这些筛选不在第一版保留占位，后续有明确需求时再增加。

### 7.1 上传人筛选

“上传人”下拉选项包括：

- 全部上传人；
- 我上传的；
- 当前知识库中实际出现过的上传人；
- 系统或历史导入。

筛选必须在服务端执行，不能只筛选当前页数据。上传人候选也必须限定在当前用户有读取权限的知识库内，不能借此读取完整用户目录。

### 7.2 上传人显示

知识资产表格增加“上传人”列，文档详情同步显示上传人。

普通用户显示顺序：

1. 显示名称；
2. 用户名；
3. 部分隐藏的邮箱；
4. 已注销用户；
5. 系统或历史导入。

管理员可以在姓名旁查看完整邮箱。普通用户不得从接口响应中得到不需要展示的完整邮箱。

### 7.3 时间范围

时间范围按文档首次上传时间筛选，不按最后更新时间计算。未选择时间范围时显示全部有权查看的文档。

## 8. 删除规则

- 文档上传人可以删除自己上传的文档，即使没有知识库的全局删除权限；
- 具有知识库删除权限的用户和管理员仍可按现有规则删除文档；
- 普通用户不能删除其他人上传的文档；
- 前端隐藏按钮不能代替后端所有权校验；
- 删除仍沿用现有文档删除、向量清理和关联数据一致性流程，不新增另一套删除逻辑；
- 本规划不提供“取消正在上传或正在处理的任务”。

## 9. 数据与接口边界

现有数据已经记录：

- 文档上传人：`documents.created_by`；
- 导入任务发起人：`document_import_jobs.requested_by_user_id`。

第一版预计不需要新增数据库字段或迁移。后续实现应复用这些字段作为唯一所有权来源，不在前端或新表中复制上传人事实。

需要补齐的接口能力：

- 当前用户任务的 30 天/全部时间统计；
- 当前用户任务按知识库、时间范围和上传相对路径的目录分页；
- 当前用户可重试任务的所有权校验；
- 文档列表的上传人筛选和上传时间筛选；
- 当前知识库内可见上传人候选；
- 根据当前查看者角色返回脱敏或完整的上传人信息；
- 删除本人上传文档的服务端所有权判定。

## 10. 权限与隐私规则

| 场景 | 普通用户 | 管理员 |
|---|---|---|
| 查看个人任务 | 仅本人 | 可使用原有全局任务监控 |
| 重试任务 | 仅本人且任务可重试 | 按原有管理权限 |
| 查看上传人 | 姓名、用户名或脱敏邮箱 | 姓名与完整邮箱 |
| 按上传人筛选 | 仅当前可读知识库内的上传人 | 当前可管理范围 |
| 删除本人上传文档 | 允许 | 允许 |
| 删除他人上传文档 | 需要知识库删除权限 | 按原有管理权限 |
| 查看 Worker 或全局队列 | 不允许 | 保持现有能力 |

## 12. 验收标准

### 12.1 个人任务

- 普通用户只能看到自己的任务；
- 左侧文件夹和右侧文件任务都只能来自所选知识库和当前用户；
- 进入子文件夹后只显示该目录的直接子文件夹和文件任务；
- 失败、处理中和已完成任务都在对应上传目录中显示；
- 修改查询参数或任务 ID 不能读取、重试其他用户的任务；
- 统计与列表都查询全部历史任务；
- 每页只返回请求的 20 或 50 条记录；
- 任务状态和错误全部使用清晰中文；
- 可恢复任务能够重试，不可恢复任务不给出无效按钮；
- 页面隐藏或没有活动任务时不继续轮询。

### 12.2 知识资产

- 筛选栏只包含标题、上传人、上传时间和筛选按钮；
- 上传人和时间筛选对全部服务端数据有效，不只作用于当前页；
- 普通用户看不到完整邮箱，管理员可以看到完整邮箱；
- 历史数据没有上传人时页面正常显示；
- 本人可以删除自己上传的文档；
- 无全局删除权限的用户不能删除其他人的文档；
- 现有文档删除与异步清理流程没有被绕过。

### 12.3 回归

- 管理员原有任务监控、重试和队列能力保持不变；
- 新增数据、替换已有文档的上传流程保持不变；
- 知识库读取、上传和删除权限保持服务端强制执行；
- 文档列表和个人任务在历史数据增长后仍保持有界请求。

## 14. 影响与风险

预计影响的执行路径：

- 上传会话创建 -> 导入任务 -> 文档生成；
- 导入任务查询 -> 个人任务统计和列表 -> 失败重试；
- 知识资产列表 -> 上传人投影与筛选；
- 文档删除 -> 所有权或知识库删除权限 -> 现有清理流程。

风险等级为 **HIGH**，原因是实现会触及身份、所有权、跨用户可见性和删除权限。实施前必须完成服务端允许/拒绝用例，实施后必须验证普通用户、其他上传人、具有删除权限的用户和管理员四类角色。

GitNexus MCP 在本次规划环境中未提供；尝试运行 `npx gitnexus analyze` 时，因全局 `tree-sitter-kotlin` 缺少 `node-gyp-build` 而失败。本规划依据仓库规定使用人工调用链检查形成；进入实施后仍需在每次修改符号前检查定义、直接调用者、相关测试和受影响执行路径。

## 15. 我的任务目录浏览

原“我的文件”页面已经调整为“我的任务”，用于同时查看上传目录、文件处理状态和已生成的知识资产。

- 进入页面后自动选择第一个具有 `insert` 权限的知识库，并请求该知识库根目录；
- 点击文件夹时，只请求该文件夹的直接子文件夹和直接文件；
- 失败、处理中和已完成文件都按上传时的相对路径显示；
- 已生成 `document_id` 的文件可以打开知识资产详情；
- 当前目录按页请求，每页只能是 20 或 50，前端不循环请求后续页面；
- 切换知识库、文件夹或页面时，中止上一轮前端请求，旧响应不得覆盖新目录；
- 不同知识库的目录和文件由服务端按 `library_id` 隔离，不在前端合并。

页面使用 `GET /me/import-task-files`。查询参数为
`library_slug`、`scope`、`path`、`page` 和 `page_size`；目录来源仅为
`document_import_jobs.relative_path`，不能使用会按文件类型拆分的 `batch_id`
代替一次文件夹上传。
